# Подключение PyDuel к Supabase

1. Откройте **SQL Editor** проекта `jnvhcvsyecubsgvcadmi` и выполните [`schema.sql`](schema.sql).
2. Проверка текущих настроек проекта показала: Email provider включён, регистрация разрешена, `mailer_autoconfirm` включён. Значит, подтверждение адреса для входа через PyDuel отключать не требуется. В PyDuel ник преобразуется в служебный адрес `ник@pyduel.invalid`, письма не используются. Сбросить забытый пароль без почты пока нельзя.
3. В **Authentication → URL Configuration** добавьте адрес, с которого будет открываться сайт, в Site URL / Redirect URLs. Локально используйте `http://localhost:8000`.
4. Раздавайте `outputs` локальным сервером, например командой `python -m http.server 8000 --directory outputs`, затем откройте `http://localhost:8000`.

Страница использует ваш publishable key. Он рассчитан на публичный клиент; **не добавляйте сюда secret/service-role key**. Таблицы закрыты RLS, а SQL выдаёт только необходимые права авторизованным ученикам.

## Что синхронизируется

- профили и присутствие в лобби (heartbeat каждые 25 секунд; неактивный профиль помечается не в сети примерно через 65 секунд);
- приглашения, срок ответа 30 секунд, принятие/отклонение;
- создание дуэли после принятия приглашения, жизни и атомарное применение первого удара раунда;
- события «печатает», «отправил решение» и «нанёс удар». Исходный код не передаётся другому игроку.

## Важные ограничения этого этапа

Проверка решения выполняется в браузере. RPC `claim_duel_hit` атомарно определяет первый заявленный правильный ответ, но сам не запускает Python и не проверяет тесты. Поэтому не используйте эту версию для рейтинговых наград: игрок может подделать вызов RPC. Для рейтинговых матчей следующим шагом нужна Edge Function/изолированный runner, который получает код, запускает скрытые серверные тесты с лимитом времени и только затем вызывает функцию урона. Скрытые тесты в клиенте не размещайте.

Текущая регистрация использует email/password Supabase Auth с вымышленным доменом. Так пароль хранит и проверяет Supabase, но восстановление пароля без email не поддерживается. Для кнопок «Выйти» и «Сдаться» используйте миграцию [`20261009_surrender_duel.sql`](migrations/20261009_surrender_duel.sql). Чтобы включить учёт рейтинга, побед/поражений и историю матчей, выполните [`20261010_rating_history.sql`](migrations/20261010_rating_history.sql) в SQL Editor Supabase. Она обновит RPC завершения дуэли, добавит Elo-изменения в записи матчей и попросит API обновить кэш схемы. История показывает до 20 последних матчей. Старые матчи сохраняются, но счётчики для них задним числом не пересчитываются.


**Примечание о рейтинговой честности:** сейчас сервер атомарно фиксирует исход и статистику, но проверка Python-решения пока выполняется в браузере. До переноса запуска скрытых тестов в Edge Function/изолированный runner игрок может подделать вызов проверки, поэтому Elo пока не является защищённым от читов.
